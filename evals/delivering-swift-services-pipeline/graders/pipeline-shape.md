PASS if the result has separate workflows for pull requests (checks and tests, plus a release-image build and smoke check, with no publication or deployment), pushes to develop (checks and tests, then build and smoke-check the release image, publish that same image, then a deploy to staging), and pushes to main (the same, then production deploy); the publish step pushes two tags, an immutable short commit SHA and the moving branch name; the tests run `swift test --disable-automatic-resolution` against the committed Package.resolved; the image is built natively for the deploy host with one named tool (a Containerfile with Docker or Apple's `container`, a static Linux SDK build, or swift-container-plugin), chosen as the project's decision, with a static Linux SDK CI build present when that path uses the static SDK; the deploy step is a single trigger bound to plain secrets that fails the run when a secret is missing rather than skipping; the summary names the deploy secrets (a platform URL, an API token, an application id) and says the application's command is `./catalog serve --migrate-database`.
FAIL if the service is given SemVer tags or GitHub releases, if the deploy step is conditional on a secret being present, if images are tagged only `latest`, if a separate migration job is added although nothing records the project choosing a `migrate` one-shot, if publication rebuilds an image other than the one smoke-checked, or if the workflows build under emulation for a different architecture than the deploy host.
